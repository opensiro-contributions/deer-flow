## 1. System boundary, rights and independent owner test

Original b4b489d7f2fb22fc88305a26e1c6e6077b497216 on bytedance/deer-flow main (2026-11-19), with frozen [Index assessment](https://github.com/opensiro/vsm-harness-index/blob/c2e43bf4750841277b3e58d8ba80314121734764/assessments/de/deerflow.md). The tested subsystem is a direct or durable delegated task within a single authorized DeerFlow Gateway workspace. Included: child execution, returned status, tool receipts, criterion checks, batch finalization, dependency continuation, the possible independent reviewer and feedback. Excluded: unrelated plugin providers, repository maintainer PR triage, discretionary third-party services, parent S5 authorization, external Index regrading and release operations.

Function ownership requirements: S1 child executes useful tasks and returns artifacts; S2/batch dependency gates must remain intact; S3/parent lead still decides work commitments, capacity and what to do after an audit; S3* is an independent, complementary source of evidence and a review decision that can trigger an authorized corrective return; S4 external future-choice loop is not borrowed from skill evolution; S5 user/host authorization and scope remain reserved. A new independently deciding actor does not gain blanket power to edit artifacts, change model policy, accept permissions or override a human.

**Function witness:** Given a worker self-report marked completed that conflicts with primary evidence, a developer-selected reviewer must be able to inspect *something the worker did not control*, decide `accept/request_changes/reject`, trigger bounded correction or hold, and observe the subsequent state and result. The worker may transport a report but cannot supply the reviewer verdict itself. A callback with no binding return is a counterexample, not C.

**Counterfactual owner test:** remove the autonomous reviewer while retaining receipt/checklist logic and human/lead inspection. Ordinary decidable file and test claims still work (native solution is good); a source-dependent undecidable acceptance claim remains advisory. If a native agent can already run independent reads, decide and bind correction using the exact same supported API, the proposed C is unnecessary.

## 3. Minimal native construction and alternatives

**Selected path:** reuse [batch_service.py](https://github.com/bytedance/deer-flow/blob/b4b489d7f2fb22fc88305a26e1c6e6077b497216/backend/packages/harness/deerflow/subagents/batch_service.py) completion interception and [status_contract.py](https://github.com/bytedance/deer-flow/blob/b4b489d7f2fb22fc88305a26e1c6e6077b497216/backend/packages/harness/deerflow/subagents/status_contract.py) metadata to establish a separate accepted-for-downstream state. Add a single opt-in reviewer adapter selected by the developer, accepting immutable child result/receipt summary plus read-only independent evidence. Respect existing `VerificationConfig` default-off semantics or replace unused fields with explicitly supported wiring. Use native batch continuation and task ownership/lease checks to request a bounded new attempt only if safe; publish a versioned decision receipt and later observed result to the lead and user. The physical number of APIs is intentionally not predetermined.

**Alternative A:** existing lead/human reads checklist and reruns task; cheapest, not independent autonomous C. **Alternative B:** a passive small-model judge scores the child's text; fails independent evidence and corrective return, even if `judge_enabled` were wired. **Alternative C:** an external app dispatches separate reviewer AgentRuns and holds dependent tasks; may satisfy the operator outcome without new core paths, and would falsify the need if it is safely composable with native identity/recovery; must test. **Alternative D:** add a general all-purpose audit framework or new parallel storage system; rejected as disproportionate to one bounded scenario.

**Likely minimum code surface:** subagent result review seam and typed outcome, scoped reviewer capability binding, batch acceptance-vs-execution state and native dependent-release integration, tests and docs. Exact file changes remain a design hypothesis, not proven implementation; native maintainers decide accepted semantics. Current RFC #4651 is an overlap and discussion route, not a permission to open a duplicate original Issue.

## 4. Falsifiers, test plan, limits

**Positive experiment (NOT_RUN):** fake a worker reporting successful citation-backed completion of a research output but with a primary source contradiction. Source-isolated reviewer must make `request_changes`, preserve the original report, stop accepted-work dependent continuation, return bounded targeted rework, and record the evidence and a corrected later accepted result. Repeat with correct report; it should pass without a needless extra run.

**Negative controls (NOT_RUN):** reviewer receives only worker prose (not independent); wrong user/workspace or missing read scope; forged approval/citation; checker exception; timeout/cancellation; lease expiry/restart; concurrent duplicate retries; lost response after side effect; attempt limit exceeded; parent STOP/approval denial; false `accept` by an untrusted reviewer. No cross-tenant data access and no external write or reexecution of uncertain side effects. Fail closed for declared mandatory audit, preserve explicit default-off baseline for existing deployments.

**Cost comparison:** original unchanged native inspection plus manual correction vs opt-in reviewer on only unresolved claims, tracking correctness, review coverage, tokens, delay, false holds, rework, integration work and maintenance. All unmeasured. A high-quality fully native/extension-only path yielding the same correction and event provenance disproves the need for a new core seam.

**Research status:** NEEDS_EVIDENCE because none of those experiments ran. **Proposal GO** means structurally arguable complete S3* C with explicit falsifiers, not shipped or validated. The record is internal fork metadata with the separate publication and owner-control requirements in [roadmap.md](roadmap.md).

## v0.18.1 native-specific developer contract — 2026-11-20 (same case)

**Candidate boundary / P0:** one opted-in *durable batch item* in the native `SubagentBatchService`; exclude global S3* middleware, generic autonomous reviewer services, direct `task()` handling and unrelated scheduler/model adaptation until this path has evidence. Keep the independently selected reviewer separate from the reporting worker; user/host and parent S5 authority stay unchanged.

1. **Observe:** [`SubagentBatchService._execute_leased_item`](https://github.com/bytedance/deer-flow/blob/e3edd05114c17d09082221a1ce1555bfbffeec16/backend/packages/harness/deerflow/subagents/batch_service.py) obtains `check_batch_acceptance` and stores `acceptance_verdict` / result artifact in `_repository.finalize_item`; native [`read_browser_batch_item`](https://github.com/bytedance/deer-flow/blob/e3edd05114c17d09082221a1ce1555bfbffeec16/backend/packages/harness/deerflow/subagents/batch_service.py) exposes a bounded owner-scoped item projection, not automatically a plugin-side capability. The [extension completed-run evidence reader](https://github.com/bytedance/deer-flow/blob/e3edd05114c17d09082221a1ce1555bfbffeec16/backend/packages/harness/deerflow/extensions/completed_run_evidence.py) has principal/owner scope, sealed revisions and bounded read but is run-scoped, **not an existing item-to-evidence join**.
2. **Decide:** the smallest possible optional adapter must bind immutable `owner_id + thread_id + batch_id + item_id + attempt + evidence_revision`, grant *only* matching read-only primary evidence, and return typed `accept / request_changes / reject` plus source pointers. A missing match, stale evidence seal, same worker-only narrative or nonindependent reviewer means **UNVERIFIED**, never accepted.
3. **Act:** add a separately fenced **acceptance-release** decision at the native item-finalization/SQL dependency seam ([`persistence/subagent_batches/sql.py`](https://github.com/bytedance/deer-flow/blob/e3edd05114c17d09082221a1ce1555bfbffeec16/backend/packages/harness/deerflow/persistence/subagent_batches/sql.py)); do not conflate completed execution with accepted output. Prevent native dependent item promotion and terminal-batch `claim_continuations` from consuming an opted-in held item; unaffected/default-off paths preserve current behavior. Only the existing owner-controlled lease/attempt machinery may admit a bounded correction when side effects are safe. Never give an untrusted reviewer arbitrary `RunManager`, SQL writes or new approvals.
4. **Return:** persist a review decision keyed to the item/attempt and re-open the same loop on a *later* result; parent/owner can read whether hold, correction or rejection actually occurred. No independent review feedback means **NO C** even if a model emits an approval label.

**Validation still required (NOT_RUN):** side-effect-safe false claim with independent artifact conflict -> hold -> no dependency/continuation -> one authorized correction -> observed receipt; true claim -> accept; wrong owner, stale seal, absent review, checker exception, cancellation/restart/lease loss, cross-worker races, retry duplication and limit exhaustion -> fail closed in opt-in mode. Test the native baseline with reviewer off. No cost/performance claim and no shipped C.

**Scoped verdict unchanged:** `GO / NEEDS_EVIDENCE` for architecturally source-grounded proposed `S3*=C`; historical Index `S3*=—` remains an accepted 2026-09-15 observation, not a present-day product flaw. If existing first-party interfaces already safely compose **independent evidence → binding hold → rework → subsequent observed result**, the extra seam is unnecessary; if not lawfully implementable with correct authority, downgrade the future implementation decision.
